
## 1. Что было сделано

Проведены два эксперимента бинарной классификации изображений: cover — изображение без внедрения, stego — изображение после WOW с нагрузкой 0,4 bpp.

- Baseline: BOSSBase 1.01, без добавления BOWS2 и без D4-аугментации.
- Expanded D4: исходная обучающая выборка BOSSBase дополнена 10 000 парами BOWS2; обучающие пары представлены в восьми ориентациях.

Использованы изображения, уменьшенные с 512×512 до 256×256 пикселей, сохранённые в PGM. 

Пара — два изображения одного исходного снимка: cover и соответствующее stego. Количество изображений вдвое больше количества пар. В обеих выборках классы сбалансированы.

Работа проверяет обнаружение следов WOW. 

## 2. Как готовились данные и проходило обучение

1. Исходные полутоновые снимки BOSSBase уменьшались до 256×256. Использовался Python-порт matlab_imresize, bicubic с антиалиасингом; версия зафиксирована в метаданных.
2. Для каждого cover формировалось stego с помощью DDE Lab WOW.exe (C++), payload 0,4 bpp. В скрипте заданы `-h 0`, `-p -1`; для каждого изображения детерминированно вычислялся отдельный seed из общего seed и имени.
3. Проверялись размер, формат, хеши и разность пикселей. Для корректной пары изменения должны принадлежать множеству −1, 0, +1; пара без изменений также не принималась.
4. Некорректные пары исключались целиком, без ручного исправления пикселей. По сохранённому протоколу baseline исключены шесть пар: две из-за переполнения 0↔255 и четыре из-за совпадающих cover после уменьшения. Сам список исключений необходимо сохранять вместе с протоколом.
5. Формировалось разбиение по исходным снимкам. Cover и stego одной пары всегда оставались вместе.
6. Обучался baseline. По сохранённой проверке его истории выполнено 400 эпох; лучший checkpoint выбран по validation на эпохе 120.
7. Для expanded добавлены 10 000 пар BOWS2 только в train. Validation и test сохранены от baseline. По ранее сохранённому полному прогону скрипта описания данных совпали SHA-256 всех 19 988 унаследованных изображений.
8. Для expanded применён режим `d4-exhaustive-v1`: четыре поворота на кратные 90° углы и отражённые варианты, всего восемь ориентаций каждой пары. Обе части пары преобразуются согласованно. Это виртуальное расширение при загрузке данных.
9. Обучение выполнялось мини-батчами по 8 пар. На каждом шаге вычислялись предсказания и cross-entropy, затем градиенты и обновление SGD. Реализация SGD и cross-entropy видна в сохранённом исходнике базового train.py; параметры expanded подтверждены его config_used.json.
10. После эпох оценивалась validation. В expanded завершены все 400 эпох; лучший результат validation получен на эпохе 368. Итоговая test-метрика хранится отдельно от истории validation.

## 3. Как выбирались изображения для выборок

В `continue_dataset(1).py`, функция `write_splits`, зафиксирован алгоритм:

1. Берётся исходный упорядоченный список имён BOSSBase.
2. Список перемешивается через `random.Random(20261025).shuffle(ids)`.
3. Первые 4 000 имён назначаются в train, следующие 1 000 — в validation, оставшиеся 5 000 — в test.
4. Из каждой группы удаляются отклонённые пары. Их место другими снимками не заполняется.
5. Для каждого оставшегося имени записываются две строки манифеста: label 0 для cover и label 1 для stego.

Таким образом, изображения не отбирались вручную по содержанию или успешности распознавания. Seed делает случайное распределение воспроизводимым при сохранении исходного порядка имён.

Соответствие «какой конкретно файл куда попал» задают `splits/manifest.csv` и `splits/split_ids.json`. Причины исключений и исходное назначение исключённых снимков хранит `splits/excluded.csv`.

## 5. Как было в статье

Сопоставление ниже относится к доступному авторскому препринту [Efficient feature learning and multi-size image steganalysis based on CNN](https://arxiv.org/pdf/1807.11428), раздел IV, таблицы VI и IX. Журнальная публикация имеет название [Depth-Wise Separable Convolutions and Multi-Level Pooling for an Efficient Spatial CNN-Based Steganalysis](https://doi.org/10.1109/TIFS.2019.2936913). Нумерацию таблиц разных версий нельзя автоматически отождествлять.

| Параметр авторского протокола | Значение |
|---|---|
| BOSSBase: train / validation / test | 4 000 / 1 000 / 5 000 пар |
| Расширение train | +10 000 пар BOWS2 |
| Train после поворотов и отражений | 112 000 виртуальных пар |
| Размер | 256×256 |
| Подготовка | MATLAB imresize и MATLAB WOW |
| Оптимизация | SGD; momentum 0,9; weight decay 0,0005; cross-entropy |
| Батч | 16 изображений, то есть 8 пар |
| Learning rate | 0,005; деление на 5 на эпохах 50, 150, 250 |
| Длительность и выбор модели | До 400 эпох, возможна ранняя остановка; выбор по validation |
| Инициализация | Заявлен Xavier |
| Оборудование | GTX 1080 Ti |
| WOW 0,4 bpp: ошибка baseline / expanded+DA | 11,8% / 6,5% |
| Соответствующая accuracy | 88,2% / 93,5% |
## 6. Наши параметры и совпадение с авторами

Параметры ниже прочитаны из `outputs/train/config_used.json` архива expanded.

| Параметр | Наш expanded |
|---|---|
| Режим | expanded-d4 |
| Эпохи | 400 |
| Seed | 20261025 |
| Батч фактический | 8 пар = 16 изображений |
| Начальная скорость обучения | 0,005 |
| Momentum | 0,9 |
| Weight decay | 0,0005 |
| Milestones | 50, 150, 250 |
| Gamma | 0,2 |
| D4 | d4-exhaustive-v1 |
| GPU | NVIDIA GeForce RTX 5090 |
| Python / PyTorch / CUDA runtime | 3.11.13 / 2.7.1+cu128 / 12.8 |

Фактическая история learning rate: эпохи 1–49 — 0,005; 50–149 — 0,001; 150–249 — 0,0002; 250–400 — 0,00004.

Основные численные гиперпараметры совпадают с указанным авторским протоколом, но есть различия:

- Наши списки train/validation/test собственные; после исключений количества немного меньше.
- У нас C++ WOW и Python-порт изменения размера. Их побитовое совпадение с MATLAB-подготовкой авторов не установлено.
- Наш expanded прошёл все 400 эпох; досрочная остановка этого запуска не применялась.
- Отличается аппаратное и программное окружение.
## 7. Результаты

| Эксперимент | Лучшая validation accuracy | Эпоха лучшей модели | Test accuracy | Test error |
