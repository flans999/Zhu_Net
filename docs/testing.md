# Проверки данных и итоговая оценка

## Что проверено для задания 185

- В комплекте перед запуском проверили все 10 000 пар, хеши файлов и отсутствие общих оригиналов между выборками. В журнале задания 185 зафиксированы проверки хешей и пикселей, проверка CUDA и пробный батч. [Отчёт проверки набора](evidence/slurm-185/dataset-audit.json)
- В архиве `Zhu-Net-SLURM-job185-2026-11-17.zip` есть итоговая оценка на 5 000 парах. По сохранённой матрице ошибок получается `(4230 + 4189) / 10000 = 84,19%` точности и `(770 + 811) / 10000 = 15,81%` ошибки. [Итоговые метрики](evidence/slurm-185/job185-metrics.json)
- SHA-256 `outputs/model.pt` совпадает с `outputs/checkpoints/best.pt`. `last.pt` содержит состояние для продолжения обучения. [Контрольные суммы](evidence/slurm-185/sha256.json)

В нашем коде класс выбирается по максимуму двух выходных оценок модели. Правило выбора порога, использованное для числа 11,8% в таблице VI, в доступном препринте отдельно не описано. На сбалансированном тесте наша доля ошибок равна средней доле ложных срабатываний и пропусков. [Таблица VI авторов](https://arxiv.org/pdf/1807.11428v1#page=8)

## Повторный тест весов из архива

В комплекте для Ubuntu есть `source/test_model.py`. Выполни команды из корня распакованного комплекта после установки окружения и проверки набора по [инструкции запуска](../smlab_ubuntu/RUN_UBUNTU.md). Путь `/путь/к/архиву/outputs/model.pt` замени путём к извлечённому файлу. Результат будет записан в отдельный JSON.

```bash
mkdir -p results
CUBLAS_WORKSPACE_CONFIG=:4096:8 .venv/bin/python source/test_model.py \
  --dataset-dir dataset --config source/config/full.json \
  --checkpoint '/путь/к/архиву/outputs/model.pt' \
  --output results/job185-test-repeat.json
```

Сверь SHA-256 набора и весов, число изображений и матрицу ошибок с архивными сведениями. Для задания 185 здесь зафиксирован тест из архива обучения. Отдельного повторного теста этих весов пока нет. Для октябрьского запуска сохранена [повторная CPU-оценка](evidence/october-boss-cpu-test.json) с совпавшей матрицей ошибок.

Проверку целостности копии репозитория и старых отчётов можно запустить из корня репозитория командой `python -B scripts/verify_publication.py`. Проверка запускается отдельно от обучения и оценки модели. [Результаты экспериментов](results.md)
