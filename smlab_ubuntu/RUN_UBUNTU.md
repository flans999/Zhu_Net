# Zhu-Net, SM Lab BOSSBase 1.01, WOW 0.4 bpp

Комплект рассчитан на Ubuntu x86_64 с RTX 5090 и установленным рабочим драйвером NVIDIA. Все команды выполняются обычным пользователем в доступной ему папке. Для установки окружения нужны интернет, `curl`, `tar` с bzip2 и `unzip`.

## Перенос и первая команда

Перенесите в одну новую папку `source.zip`, `dataset.tar.gz`, `SHA256SUMS` и этот `RUN_UBUNTU.md`. Перейдите в эту папку. Первой выполните проверку контрольных сумм.

```bash
sha256sum -c SHA256SUMS
unzip source.zip
tar -xzf dataset.tar.gz
```

Архив исходников содержит `source/`, `audit/`, `reference/`, `setup_env.sh` и `run.sh`. Архив датасета создаёт `dataset/` с исходными файлами изображений, манифестом и списками ID.

## Окружение без sudo

```bash
bash setup_env.sh
```

Скрипт устанавливает локальную micromamba в `.tools/` и Python 3.11.13 в `.venv/`. Версия загрузчика micromamba и его SHA-256 сохраняются в `environment_evidence/`. При наличии Python 3.11.13 можно использовать его для создания локального venv.

```bash
SMLAB_PYTHON=/absolute/path/to/python3.11 bash setup_env.sh
```

Ключевые версии взяты из подтверждённого прежнего baseline на RTX 5090. Используются Python 3.11.13, PyTorch 2.7.1+cu128, torchvision 0.22.1+cu128, torchaudio 2.7.1+cu128, CUDA runtime 12.8, NumPy 2.2.6 и Pillow 12.0.0. CUDA-библиотеки устанавливаются с wheel-пакетами. Исходная запись окружения сохранена в `reference/baseline_environment.lock`. Её локальные `file://` пути относятся к сборке прежнего образа. Полная побитовая идентичность пересозданного окружения не подтверждена. Фактический список пакетов записывается в `environment_evidence/installed.lock`.

Команды установки соответствующей версии PyTorch и загрузки micromamba сверены с официальными инструкциями. [PyTorch](https://pytorch.org/get-started/previous-versions/), [micromamba](https://mamba.readthedocs.io/en/latest/installation/micromamba-installation.html)

## Проверка GPU и датасета

```bash
bash run.sh gpu
bash run.sh validate
```

GPU-проверка запускает `nvidia-smi`, проверяет версию PyTorch/CUDA, наличие `sm_120` в сборке и выполняет CUDA-операцию. При недоступном драйвере или GPU обратитесь к оператору Ubuntu. Результат сохраняется в `environment_evidence/gpu.json`.

Проверка датасета читает все 20 000 изображений, проверяет SHA-256, размер 256×256, режим L, ненулевые разности в пределах −1…+1, состав каждой пары, списки ID, размеры выборок, отсутствие пересечений ID и одинаковых cover между выборками. Результат сохраняется в `results/dataset-validation.json`.

## Пробный запуск

```bash
bash run.sh smoke
```

Выполняются три шага обучения по 8 пар, короткая validation и сохранение checkpoint в `results/smlab-smoke-seed20261025/`. Успешное завершение отмечается `TRAINING_SMOKE_PASS`. При повторном запуске используйте другую папку через прямой вызов `source/train.py` либо возобновите нужный запуск явно. Полный запуск использует отдельную папку.

## Обучение и итоговый test

```bash
bash run.sh train
```

Выполняются 400 эпох с 8 парами на минибатч. В конце каждой эпохи оценивается validation. Checkpoint выбирается по максимальной validation accuracy. После 400 эпох на выбранном checkpoint автоматически оценивается весь test из 5 000 пар, сохраняются метрики и сравнение с прежним baseline. Если 8 пар не помещаются в память, запуск завершится с ошибкой. Размер минибатча задаётся явно и проверяется.

Лог находится в `logs/smlab-full.log`. Результаты находятся в `results/smlab-wow04-seed20261025/`.

- `metrics.json` содержит историю эпох, лучшую validation accuracy и итоговые test accuracy, loss, precision_stego, recall_stego, f1_stego, число изображений и confusion_matrix.
- `comparison_with_baseline.json` содержит обе test-оценки и их разницы.
- `training_result.json` фиксирует завершение 400 эпох и фактический batch.
- `config_used.json` и `runtime_info.json` фиксируют параметры, окружение, датасет и SHA-256 начального состояния модели.
- `checkpoints/last.pt` содержит состояние для продолжения обучения.
- `checkpoints/best.pt` и `model.pt` содержат модель, выбранную по validation.

Для продолжения после прерывания выполните следующую команду.

```bash
bash run.sh resume
```

Для повторного итогового теста выполните следующую команду.

```bash
bash run.sh test
```

Повторный test сохраняется в `results/smlab-wow04-seed20261025/test_evaluation.json` с эпохой и SHA-256 checkpoint, хешем датасета и метриками в прежнем формате. Классы имеют номера 0 для cover и 1 для stego. Строки confusion_matrix соответствуют истинному классу, столбцы предсказанному.

## Данные, разбиение и сопоставимость

Исходные изображения предоставлены как SM Lab BOSSBase 1.01, 256×256, WOW 0.4 bpp. Проверены все ID 1…10 000. Принадлежность пар подтверждена совпадающими числовыми именами и попиксельными разностями. Сам алгоритм WOW и payload 0.4 bpp указаны по происхождению набора. Одних разностей пикселей недостаточно для доказательства этих параметров.

Обнаружены одинаковые cover в четырёх группах ID.

- 5341 и 5536
- 5342 и 5537
- 5343 и 5538
- 5344 и 5539

Соответствующие stego различаются. Все 10 000 пар сохранены. Всего имеется 9 996 различных cover. Каждая группа одинаковых cover целиком помещена в одну выборку. Сначала группы упорядочиваются по минимальному числовому ID, затем перемешиваются `random.Random(20261025)`. Выборки последовательно заполняются целыми группами до 4 000 / 1 000 / 5 000 пар. Алгоритм находится в `source/split_pairs.py`, результат в `dataset/splits/manifest.csv` и `*_ids.txt`. SHA-256 каждого исходного файла и результаты попиксельной проверки сохранены в `audit/pairs.csv`.

Это наше воспроизводимое разбиение. Совпадение конкретных снимков со статьёй не подтверждено. Сохранены настройки предыдущего baseline, включая код модели, SRM-ядра, порядок инициализации, seed, деление uint8 на 255, SGD с learning_rate 0.005, momentum 0.9, weight_decay 0.0005, milestones 50/150/250 и gamma 0.2. Фактические learning rate меняются на эпохах 50, 150 и 250 по прежнему коду. Используется BOSSBase без аугментации.

Прежний baseline оценивался на 4 998 парах test, новый использует 5 000. Различаются подготовка данных и состав выборок. Сравнение отражает результаты одиночных запусков при этой замене датасета и разбиения.

Отчёт проверки исходных пар находится в `audit/audit.json`. Отчёт проверки собранного комплекта и архивов находится в `WINDOWS_VALIDATION.json` рядом с архивами. На Windows проверены все хеши и пиксели упакованного датасета, воспроизводимость разбиения, состав архивов и компиляция Python-файлов. Доступ к RTX 5090 в этой сессии не подтверждён. CUDA-проверка и пробное обучение требуют выполнения приведённых команд на Ubuntu.
